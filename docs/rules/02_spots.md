# スポット

出典の略号は [資料一覧](../sources/08_sources_and_open_questions.md) を参照。

## 配置・系列・在庫

- スポットは平地上にあり、1セルに最大1つ（S p.4、Q18・Q34）。
- スポット数の最小値はエージェント数、最大値は縦幅・横幅の大きい方（Q15）。
- `brand` は整数の系列識別子、`pos` はセルID、`stocks` は最大在庫数（F p.1、Q40）。
- 各スポットに1つの系列があり、系列ごとにうどんの種類が異なる（G p.9）。
- 系列数は1～スポット数。位置と系列は試合中に変化しない（G p.9）。
- 1巡回車が獲得できる玉数に上限はない（G p.9）。

在庫の規則（G p.10）：

- 在庫は毎日の開始時に最大値へ回復する。
- 最大在庫は1～エージェント数。
- 在庫はチームごとに独立し、他チームの獲得では減らない。

## 獲得条件

ステップ1～Nの反映フェーズで、巡回車の現在地がスポットなら獲得判定する。
在庫があり、同じ巡回車が同じ日にそのスポットで未獲得なら1玉獲得する。
獲得済みなら待機や再訪で追加獲得できない（Q6～Q8・Q17）。

「到着したときだけ」のイベントではない。日をまたいでスポット上にいる場合も、
ステップ1以降に滞在していれば獲得できる。ステップ0では獲得しない。
移動予約中も位置は出発セルなので、スポットから移動を予約していても、
移動完了前のステップで獲得できる（S p.4、巡回車E）。

在庫が不足する同時獲得では、初期マップの `agents` 配列の先頭に近い車両を優先する（Q26）。
在庫切れで獲得できなかった車両を「獲得済み」と扱わない。

例：在庫1にBとGが同時に到着し、Bの添字が小さい場合、
Bが1玉獲得し、Gは獲得しない（S p.4）。

## 管理する状態

実装上は、チーム内の当日残在庫、車両×スポットの当日獲得済みフラグ、
日ごとの獲得系列集合、試合全体の獲得系列集合、総玉数を管理する。
同系列の別スポットを訪れることは「同一スポット1日1回」制限とは別。
