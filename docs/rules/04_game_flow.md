# 試合進行・道路渋滞

出典の略号は [資料一覧](../sources/08_sources_and_open_questions.md) を参照。

## 試合前と各日

1. マップ構成、全日の回答時間・ステップ数、初期位置、燃料上限等を取得する（F p.1）。
2. 車両種別を回答する（F p.3）。
3. 各日開始時に自他チームの車両状態と道路状態を取得する（F p.2）。
4. 全車両の1日分の行動計画を、当日の締切までに提出する。
5. 結果が反映され、翌日の回答時間が直ちに始まる。実況用の休止時間はない（Q54）。

各日の規定ステップ数は全車両共通。
`W+H <= N <= 4*(W+H)` の範囲で、日によって異なる場合がある。
全日分が試合前に与えられ、その後変更されない（Q9・Q20・Q44・Q45・Q59）。

初日にも車両の位置・燃料が与えられる（Q61）。
翌日の位置は前日終了位置、燃料は前日残量を使う（Q19・Q55）。
初日は満タン・全道路順調・在庫最大。毎日の開始時に在庫を最大まで補充する（G pp.11～12）。

入力 `day` は「情報提供前の日付」で、初日が0（F p.2）。
計画対象は `daySteps[day]`、人向けの第 `day+1` 日に対応する。

## 回答受付

各車両の行動時間の合計をNに一致させる。時間が余るなら待機を明示する。
長すぎる計画も短すぎる計画も、実行不可能な移動も不正。
1車両でも不正なら回答全体をリジェクトする（Q6、F p.3）。
締切内は再提出でき、最後に受理された有効回答を採用する。
有効・無効が通知され、マップ更新には若干の遅延があり得る（G p.12）。

締切までに有効な回答がなければ、全車両がその日の開始位置でNステップ待機する（Q55）。
失格と同義ではない。待機時にも通常の獲得・補給・交通量処理が適用されるという理解になる。

## 道路交通量

反映フェーズで全車両の移動を反映した後の位置を数える（Q27）。
ステップ0は数えず、ステップ1～Nを数える。移動予約中は元のセルの滞在として数える。
待機中の車両も含める（S p.4）。

以下はG p.9の集計・判定式。同じ日の道路状態は全チーム共通で、その日中は変化しない。
日dの道路セルcへの全チーム・全車両の滞在ステップ総数をT[d,c]、
チーム数をPとする。

- 第1日：全道路順調。
- 第2日：第1日の交通量 `T[1,c]/P` を使用。
- 第3日以降：前日と前々日の交通量の和 `(T[d-1,c]+T[d-2,c])/P` を使用。

|判定値v|状態|
|---|---|
|v < busyThreshold|順調|
|busyThreshold <= v < jammedThreshold|混雑|
|jammedThreshold <= v|渋滞|

混雑基準は1～5、渋滞基準は2～10の正の整数（Q13・Q30）。
道路状態だけが配布され、実際の交通量は配布されない（Q12）。
したがって翌日の渋滞の完全再現には他チームの行動情報が不足する。

G p.9は2日分を合算してチーム数で割ると定義しており、日数2では割らない。
実装では滞在総数と `基準値*P` を比較すれば、除算や丸めを行わず定義どおりに判定できる。
前日ごとに整数除算してから足すことは避ける。
